Example · Advanced setup

Embedding the Verbatim AI chatbot widget

This page is the demo. The three snippets below are the exact code this file contains — nothing else is needed to put an AI assistant, answering from your own documents, on any website.

Before you begin

Two values are mandatory. Without either one the widget logs an error and refuses to mount.

Value What it is Where to get it
accessToken Short-lived token sent as the X-Access-Token header on every request. Needs the session:read, session:create, post:read and post:create scopes. POST /v1/auth/access-token
corpusIds The document collections the assistant is allowed to answer from. At least one id. GET /v1/corpus/, or the chip under the title on your corpus page

The token is visible in the page source. Use a short-lived, org-scoped access token — never a long-lived master secret or a raw JWT.

The setup, in three steps

1

Add a container element

An empty <div> anywhere in your <body>. It only marks the mount point — the widget itself renders as a floating launcher, so the container's position on the page does not matter.

html 
<!-- 1. A container element for the widget -->
<div id="verbatim-chatbot"></div>
2

Load the widget from the CDN

One script tag. It exposes a single global, ChatbotWidget. Styles are bundled: the widget renders inside a Shadow DOM and injects its own CSS, so there is no stylesheet to add and your site's CSS cannot leak into it.

html 
<!-- 2. Load the widget from the Verbatim CDN -->
<script src="https://cdn.verbatim-ai.com/widget/chatbot/v1/chatbot-widget.iife.js"></script>
3

Mount it

Call mountChatbotWidget with a CSS selector (or a DOM element) and your options. This inline script must come after the CDN script tag, otherwise ChatbotWidget is not defined yet.

html 
<!-- 3. Mount it -->
<script>
    ChatbotWidget.mountChatbotWidget("#verbatim-chatbot", {
        // Connection
        accessToken: "YOUR_ACCESS_TOKEN",
        corpusIds: ["YOUR_CORPUS_ID"],
        model: "gemma4",
        lang: "en",

        // Branding
        title: "Acme Assistant",
        imageUrl: "https://example.com/logo.png",
        imageWidth: "120px",
        greeting: "Hi! 👋 How can I help you today?",
        greetingOutside: true,

        // Suggested prompts
        chatPrompts: [
            "What can you help me with?",
            "How do I get started?",
            "Contact support"
        ],

        // Appearance
        theme: {
            preset: "boring",
            tokens: {
                headerBackground: "linear-gradient(90deg, #0f172a, #1e293b)",
                openButtonBackground: "#0f172a",
                badgeBackground: "#f97316"
            }
        },

        position: { mode: "trigger", gap: 10 },

        // Layout
        messageInputPosition: "bottom"
    });
</script>

Everything else has a sensible default — title, theme, greeting, position, suggested prompts. See options.md and branding.md for the full reference.

What this page actually does

This file contains exactly that code, at the bottom of the <body> — with one addition: it checks whether the placeholders have been replaced before mounting, so that opening the unedited file does not fire an authenticated request with a fake token. On your own site you would drop that guard and call mountChatbotWidget directly.

If it doesn't work

Symptom Likely cause
ChatbotWidget is not defined The inline script runs before the CDN script has loaded. Put it after, or wait for DOMContentLoaded.
[ChatbotWidget] Invalid configuration accessToken is empty, or corpusIds is missing/empty.
Mounts, but messages fail The token is invalid, expired, or missing one of the four required scopes — the API answers 401.
Nothing appears The container element does not exist in the DOM at mount time.
Answers ignore your documents Wrong corpusIds for your account.
